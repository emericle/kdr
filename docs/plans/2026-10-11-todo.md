## Phase 3 — Performance

- [x] `database.py:260` `get_price_at_interval_start` — collapse 2+ queries into
      one per symbol across all durations, or serve from `IndexStore`
      *Done:* `get_prices_at_interval_starts(symbol)` reads the latest record once
      and measures every duration against that same anchor, so a symbol costs one
      anchor query plus one per duration instead of two to four each. Results are
      cached for the minute they were read in and the cache is dropped on every
      write. `get_price_at_interval_start` is now a thin wrapper over it, and both
      `src/web_server.py` summary paths call the batched form.
- [x] `MarketDataModel` (`database.py:79-89`) — unique constraint on
      `(symbol, timestamp)` plus insert-then-skip, to stop duplicate bars
      *Done:* `Index("market_data_bar_unique", symbol, timestamp, unique=True)` on
      the model (the string-name form does not attach to the table, the Column form
      does), `schema.sql` carries the matching `CREATE UNIQUE INDEX`, and
      `add_market_data` deduplicates within a batch, checks the batch against what
      is stored with one query, and falls back to one-record inserts if a
      concurrent writer wins the race.
- [x] `scraper.py:65` — `RotatingFileHandler` instead of one log per run
      (`logs/` is 390 MB / 47 files)
      *Done:* one `logs/kdr.log` rotating at 10 MB with five backups. `force=True`
      on `basicConfig` is what makes it take effect at all — `src/database.py` runs
      a `basicConfig` first during import, and a second call without `force` is
      dropped. `bin/daemon.sh`, `bin/start.sh`, `bin/local-start.sh` and
      `bin/local-stop.sh` now point at that file and send the background process's
      own stdout/stderr to `/dev/null` instead of appending a second copy of every
      record to a per-run file, which is where the 390 MB was actually coming from.
